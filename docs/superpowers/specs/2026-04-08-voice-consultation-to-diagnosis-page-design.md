# Voice Consultation Integration with Diagnosis Recommendation Page

## Summary

Integrate the voice consultation (语音问诊) flow into the existing ConsultationPage so that after voice recording and LLM processing, the generated chief complaint and history of present illness are filled into ConsultationPage, which then automatically triggers diagnosis recommendation. This eliminates the intermediate VoiceConsultationResult editing page.

## Current State

Two independent consultation flows exist:

1. **Voice flow:** VoiceCapsule -> Aliyun speech recognition -> LLM generates full structured record -> VoiceConsultationResult (edit/confirm) -> submit to HIS
2. **Form flow:** ConsultationPage symptom selection -> dynamic forms -> generate chief complaint/HPI -> diagnosis recommendation -> treatment suggestions -> submit to HIS

## Target State

Voice flow feeds into the form flow's diagnosis recommendation:

```
VoiceCapsule (recording)
  -> Aliyun speech recognition (realtime)
  -> User stops recording
  -> LLM generates structured record (loading shown on VoiceCapsule)
  -> Extract chiefComplaint + historyOfPresentIllness
  -> Navigate to ConsultationPage (voice mode)
  -> Auto-fill chiefComplaint + historyOfPresentIllness
  -> Skip symptom selection UI
  -> Auto-trigger diagnosis recommendation
  -> Continue with existing ConsultationPage workflow (treatment suggestions, report, etc.)
```

## Design Decisions

- **Only chief complaint and HPI are passed** from the voice flow to ConsultationPage. Diagnoses, medications, and other fields generated by the voice LLM are discarded -- ConsultationPage's own AI re-generates these via its diagnosis recommendation pipeline, keeping the recommendation logic consistent.
- **VoiceConsultationResult is bypassed**, not deleted. The component and `voice-result` view type remain in the codebase for potential future use.
- **Loading is shown on VoiceCapsule** during LLM processing (e.g., "正在生成病历..."). The transition to ConsultationPage happens only after processing completes, avoiding an empty/loading state in ConsultationPage.
- **No switching from voice mode to form mode** within the same session. User must cancel and re-enter if they want to use the form flow instead.

## Architecture

### Data Flow

```
App.vue
  voiceRecord: Ref<{ chiefComplaint: string; historyOfPresentIllness: string } | null>

useVoiceConsultation.handleVoiceStop()
  1. Keep VoiceCapsule view, show loading indicator
  2. Call LLM (unchanged)
  3. Parse response, extract chiefComplaint + historyOfPresentIllness
  4. Set App.vue voiceRecord ref
  5. Navigate to 'consultation' view
  6. Resize window to WINDOW_SIZES.CONSULTATION

ConsultationPage (props)
  voiceRecord?: { chiefComplaint: string; historyOfPresentIllness: string }

  watch(voiceRecord):
    1. Set isVoiceMode = true
    2. Fill generatedRecord.chiefComplaint and historyOfPresentIllness
    3. nextTick -> trigger diagnosis recommendation
```

### ConsultationPage Voice Mode

When `isVoiceMode = true`:
- Hide left symptom sidebar (`symptom-sidebar`)
- Hide dynamic symptom forms
- Show chief complaint / HPI textarea area directly (full width)
- Auto-trigger diagnosis recommendation after fill

When `isVoiceMode = false` (default):
- No change to existing behavior

### Component Prop Changes

**ConsultationPage.vue:**
```typescript
const props = defineProps<{
  initialPatientData?: any;
  assistTrigger?: {
    kind: ConsultationAssistAction;
    token: number;
  } | null;
  voiceRecord?: {          // NEW
    chiefComplaint: string;
    historyOfPresentIllness: string;
  } | null;
}>();
```

## Files Changed

| File | Change |
|------|--------|
| `src/composables/useVoiceConsultation.ts` | Modify `handleVoiceStop`: show loading on capsule, after LLM completes store result in voiceRecord ref and navigate to consultation view with consultation window size |
| `src/App.vue` | Add `voiceRecord` ref, pass as prop to ConsultationPage, clear on consultation close |
| `src/components/ConsultationPage.vue` | Add `voiceRecord` prop, add `isVoiceMode` computed/ref, add watcher to auto-fill and trigger diagnosis, conditionally hide symptom sidebar and forms in template |

## Edge Cases

| Scenario | Behavior |
|----------|----------|
| LLM generation fails | showToast error, exitWork back to ball (unchanged) |
| Empty transcription | showToast "未能识别到有效语音", exitWork (unchanged) |
| LLM detects irrelevant content | showToast error, exitWork (unchanged) |
| User clicks cancel in ConsultationPage | Emit `close`, App.vue clears voiceRecord, return to ball |
| User wants to switch to form mode | Not supported; must cancel and re-enter via form flow |
